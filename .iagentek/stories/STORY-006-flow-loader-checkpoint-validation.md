# Story: Flow loader rejects duplicate checkpoint.id

## Story
As **a future maintainer (or the reconciliation logic in STORY-003)**, I want **the flow loader to fail loudly if two phases share a `checkpoint.id` within the same flow**, so that **STORY-003's reconcile heuristic can safely assume each `checkpoint.id` maps to exactly one phase**.

## Acceptance Criteria
- [ ] `loadFlowDefinition(name, lang)` calls `validateUniqueCheckpointIds(flow)` before returning.
- [ ] If two phases have the same `checkpoint.id`, an error is thrown with format: `Flow '<flow.name>' has duplicate checkpoint.id '<id>' (phases '<phase1.id>' and '<phase2.id>')`.
- [ ] If a phase has no `checkpoint` field, it is ignored by the validation.
- [ ] All 4 existing flows (greenfield, brownfield, bugfix, refactor) pass the validation (regression: don't break what works).
