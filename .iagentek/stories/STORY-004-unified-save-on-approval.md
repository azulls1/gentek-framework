# Story: Unified save on checkpoint approval (close approve↔completed gap)

**ID:** STORY-004
**Feature:** `specs/memory-system.md` (v0.4.5)
**Sprint:** S1-bugfixes
**Plan:** `plans/memory-bugfixes.md`

## Story
As **any IAgentek user**, I want **the checkpoint approval and phase-completion to be persisted in a single atomic write**, so that **a crash between the two cannot leave my state inconsistent in the first place** (defense-in-depth alongside STORY-003).

## Acceptance Criteria
- [ ] `CheckpointManager.run()` no longer calls `state.recordCheckpoint()` internally.
- [ ] The orchestrator, on `decision === 'approve'`, builds the new `state` slice and calls `state.save({ checkpoints: [...prev, newCheckpoint], completedPhases: [...prev, phase.id], currentPhase: null })` in ONE call.
- [ ] If `state.save()` fails (atomic write from STORY-001 ensures original integrity), the cycle aborts cleanly with a clear error.
- [ ] Modes `skip` and `auto` still work — they short-circuit before reaching the handler and the orchestrator handles the save path uniformly.
- [ ] No double-save of `recordCheckpoint` + `markPhaseCompleted` paths remains in the code (grep verifies).
