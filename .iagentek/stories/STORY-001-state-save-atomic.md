# Story: Atomic state.json writes

**ID:** STORY-001
**Feature:** `specs/memory-system.md` (v0.4.5)
**Sprint:** S1-bugfixes
**Plan:** `plans/memory-bugfixes.md`

## Story
As **any IAgentek user**, I want **`state.json` to never get truncated or corrupted by a crash mid-write**, so that **`iagentek resume` after any kind of interruption finds a valid state file**.

## Acceptance Criteria
- [ ] `StateManager.save()` writes to a uniquely named `.tmp` first (`state.json.<pid>.<6-hex>.tmp`), `fsync`s the fd, then `rename`s to final path.
- [ ] On `rename` failure with `EBUSY` / `EPERM` / `EACCES`, retries up to 5 times with backoff `[10, 30, 80, 200, 500] ms + jitter`.
- [ ] If all retries fail, the `.tmp` is cleaned and the error is rethrown with file path + reason.
- [ ] On POSIX, the parent directory fd is `fsync`'d after rename (silent if `EINVAL`).
- [ ] If `fsync` on the file fd throws `EINVAL` (network FS), the write proceeds (rename is the committer).
- [ ] The public signature of `save()` is unchanged.
