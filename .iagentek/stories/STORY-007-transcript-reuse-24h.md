# Story: Reuse recent transcripts to avoid LLM re-spend on resume

**ID:** STORY-007
**Feature:** `specs/memory-system.md` (v0.4.5)
**Sprint:** S1-bugfixes
**Plan:** `plans/memory-bugfixes.md`

## Story
As **any IAgentek user resuming a cycle after a crash**, I want **the orchestrator to reuse the existing phase transcript if it was written less than 24 hours ago**, so that **I don't pay for the same LLM call twice when a crash happened after the LLM responded but before the checkpoint**.

## Acceptance Criteria
- [ ] `Orchestrator.runPhase(phase)` checks `.iagentek/.transcripts/<phase.id>.md` before calling the provider.
- [ ] Reuse triggers when: file exists AND mtime is <24h ago AND file size is >200 bytes (skip placeholders).
- [ ] On reuse, log `♻ Reusing transcript from <human-readable age> for '<phase.name>'.` and return the file content as if it were the LLM output.
- [ ] On reuse, the rest of the phase pipeline runs unchanged (scrubSecrets, extractAndWriteArtifacts, transcript write, checkpoint).
- [ ] Builtin agents (`phase.agent.startsWith('__')`) never reuse — they always run fresh.
- [ ] Reuse window is configurable in `iagentek.config.yaml` as `transcripts.reuseWindowHours` (default 24); not exposed as CLI flag in v0.4.5.
