# Story: Reconcile approve↔completion gap at orchestrator start

**ID:** STORY-003
**Feature:** `specs/memory-system.md` (v0.4.5)
**Sprint:** S1-bugfixes
**Plan:** `plans/memory-bugfixes.md`

## Story
As **any IAgentek user**, I want **the orchestrator to detect and auto-repair the inconsistent state where a checkpoint was approved but the phase wasn't marked completed (crash recovery scenario)**, so that **`resume` doesn't re-run an already-approved phase and waste tokens**.

## Acceptance Criteria
- [ ] `Orchestrator.run()` calls a new private method `reconcileState(state)` immediately after loading state and BEFORE the main phase loop.
- [ ] For each `phase` in the flow that has a `checkpoint`, if `state.checkpoints` contains the checkpoint's `id` AND `state.completedPhases` does NOT contain the `phase.id`, the orchestrator calls `state.markPhaseCompleted(phase.id)` and logs `⤴ Reconciling '<phase.name>': approved but not marked complete.`.
- [ ] Reconcile never calls the LLM provider.
- [ ] If multiple phases need reconciliation (rare), all are reconciled before the loop starts.
- [ ] If no inconsistencies exist, reconcile is silent (no log output).
