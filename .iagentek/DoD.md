# Definition of Done — Memory System feature

Applies to every story across all three releases (v0.4.5, v0.4.6, v0.5.0) unless explicitly overridden in a sprint-specific DoD.

## Per-story DoD

A story is considered DONE only when:

- [ ] **Code merged to `main`** via PR (no direct pushes to main).
- [ ] **All Acceptance Criteria** in the story file are checked and verified.
- [ ] **All associated tasks** in the corresponding `tasks/<feature>.md` are marked `done`.
- [ ] **Tests pass** in CI matrix:
  - Node 18.x, 20.x, 22.x
  - Ubuntu latest, Windows latest
  - All previously-passing tests still pass (no regressions).
- [ ] **Type-check passes** across all three packages (`npm run build` clean, no `tsc` errors).
- [ ] **Linting passes** if configured (currently no lint step — skip).
- [ ] **Security review passed** for any code that touches:
  - File-system writes outside `.iagentek/` ↔ require explicit reviewer approval.
  - LLM prompt construction ↔ verify `wrapUntrusted` used for any external content.
  - Parser of any LLM-emitted block ↔ verify schema-closed + sanitization (v0.5.0).
- [ ] **No secrets** committed (`git secrets --scan` clean, or manual inspection of diff).
- [ ] **Documentation updated**:
  - `CHANGELOG.md` entry under the upcoming version section.
  - `README.md` updated if the story changes user-visible behavior.
  - `docs/memory-system.md` updated if the story affects the memory subsystem contract (v0.4.6+).
- [ ] **Backwards compatibility** preserved unless the story is explicitly a breaking change (must be flagged in CHANGELOG with migration note).

## Per-release DoD (sprint exit)

In addition to per-story DoD, a release is shippable when:

- [ ] **Version bumped** in all three `package.json` files (`@iagentek/cli`, `@iagentek/core`, `@iagentek/method`) in lockstep.
- [ ] **Internal dependencies** updated: `cli` depends on the new version of `core` and `method`.
- [ ] **Manual smoke E2E** executed against:
  - A fresh project (`init` → `cycle` → `resume`).
  - An existing v0.4.4 project being upgraded (backwards-compat path).
- [ ] **CI matrix green** on the release commit.
- [ ] **CHANGELOG section** for the version is complete and accurate, lists user-visible changes + any breaking changes.
- [ ] **README version badge** points to the new version.
- [ ] **npm publish** completed for all three packages in correct order: `method` → `core` → `cli`.
- [ ] **GitHub release** created with the CHANGELOG section as the body.
- [ ] **Plugin marketplace.json** updated if any slash command added/removed (v0.5.0).

## Definition-of-Done for security-sensitive changes (v0.5.0 scribe)

In addition to all above:

- [ ] **All 8 blocking mitigations** from the red-team review have a dedicated test that demonstrates the mitigation works (see `plans/memory-scribe.md`).
- [ ] **Adversarial E2E** executed: crafted poisonous input → verified that no preference was applied, warning logged, cycle completed.
- [ ] **Residual risk** for hostile LLM providers documented explicitly in `docs/memory-system.md` (no false sense of security).
- [ ] **Diff review** of every LoC touching the scribe parser by a second pair of eyes (or a follow-up red-team review agent).

## What "Done" is NOT

- "Code compiles" alone is not Done.
- "Tests pass on my laptop" alone is not Done (must be CI-verified across the matrix).
- "I'll add tests later" is not Done.
- "Works in interactive mode" without verifying `fully-autonomous` mode is not Done (the autonomy promise of the framework requires both work).
