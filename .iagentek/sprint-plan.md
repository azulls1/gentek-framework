# Sprint Plan — S1-bugfixes (v0.4.5)

**Feature:** `specs/memory-system.md` — Release 1
**Plan:** `plans/memory-bugfixes.md`
**Target release:** v0.4.5 (npm: `@iagentek/cli@0.4.5`)
**Estimated duration:** ~3 working days
**Complexity (from plan):** M (≈300 LoC + 22 tests)

## Sprint goal

Ship the foundational atomicity and crash-recovery primitives that the memory system (v0.4.6, v0.5.0) depends on, as an independently valuable patch release. After this sprint:

- `state.json` cannot be corrupted by a crash mid-write.
- A crash between checkpoint approval and phase completion auto-reconciles on next `resume`, without re-spending LLM tokens.
- Recent phase transcripts are reused on resume instead of triggering a new LLM call.
- The `CheckpointManager.run()` signature exposes `notes` for use by v0.4.6 and v0.5.0.

## Dependencies external to this sprint

- None. v0.4.5 stands alone.
- v0.4.6 (next sprint) consumes the `notes` from `CheckpointManager.run()` — but v0.4.5 ships it unused by current code; that's intentional (API ready for future).

## Risks accepted

- **Patch release with breaking API change in `CheckpointManager.run()`.** Mitigation: documented in CHANGELOG; zero known external consumers verified by `npm dependents @iagentek/core`. If a consumer surfaces post-release, we issue v0.4.6 with a deprecation shim.
- **Windows antivirus + OneDrive edge cases**. Mitigation: retry with backoff covers ≥99%; warning at init if path contains `OneDrive`; documented in `docs/troubleshooting.md` (added in this sprint).

## Out of scope (defer to v0.4.6+)

- Lockfile for concurrent execution prevention.
- Detection of duplicate `init` over existing project.
- Telemetry / stats.
